# Jira 与 Linear 工单接入

当 `$triage-finding` 导入 Jira 或 Linear 问题时，请使用本参考。在规范化之前检索所请求的工单内容。切勿仅凭标识符、标题片段或仓库代码推断无法访问的工单内容。

## 来源检索

对于 Jira，在可用时使用 Atlassian Rovo 连接器：

- 对于可重复的导入集合，优先使用结构化 JQL，并按稳定字段（如 key 或创建日期）排序。仅使用自然语言搜索来从模糊短语中发现云/站点、项目、问题族或首个匹配的 key。发现后，切换到 JQL 或精确问题获取。
- Jira 文本搜索会将标点符号分词。如果带连字符的标记（如 `KAN-PROMPTFOO-SYNTH`）未返回任何行，则放宽到稳定标记（如 `PROMPTFOO`），然后在分诊前过滤返回的摘要以匹配精确的问题族。
- 当连接器支持时，直接获取精确的问题 URL 或 key。对于项目族或已保存的查询，使用 JQL 并保留 JQL 字符串作为来源溯源。

对于 Linear，直接获取精确的问题 URL 或标识符。当用户提供团队、项目或搜索短语时，仅使用搜索结果来识别预期的问题集合，然后在规范化之前获取每个选中的问题。

## Linear 父问题与子问题选择

对于精确的 Linear 问题，首先获取父问题。然后使用连接器的父级过滤器列出其直接子问题。在决定是否存在子问题之前，请遍历完直接子问题列表的所有分页。

当父问题存在直接子问题时：

1. 显示直接子问题的数量以及每个子问题的标识符和标题。此列表是选择元数据，而非导入的发现内容。
2. 在获取任何子问题的完整内容之前，询问是否包含该层级。
3. 如果用户拒绝，则不获取或规范化这些子问题。
4. 如果用户批准，检查所选发现数量是否仍在结果限制内，然后获取每个已批准子问题的完整内容。
5. 为每个已批准的问题列出直接子问题，遍历完所有分页，并按父问题分组下一级的标识符和标题。如果存在另一层级，则在获取其完整内容之前，在下一深度重复确认。

不要将某一层级的批准解释为对更深层后代的批准。如果某一层级没有子问题，则继续，不再询问子问题。

将最初提供的父问题与其子问题分开分类：

- 当其标题和正文包含清晰的独立漏洞声明时，将父问题作为分诊项包含。
- 当其仅组织或总结子发现时，将其排除。
- 如果父问题混合了集合上下文与可能的独立声明，且分类不明确，请解释歧义并在规范化之前询问是否包含父问题。

每个选中的问题保留一个结果。使用确定性的广度优先树顺序：选中时首先包含父问题，然后按创建时间排序每个已批准的深度，以问题标识符作为决胜条件。在引用中保留源标识符和父级关系。

`triage-finding/v0` 结果最多接受 250 个发现。在为已批准的层级获取完整内容之前，计算选中时的父问题数量加上所有先前导入和新批准的问题。如果总数将超过 250，则停止并报告数量。要求用户按深度、状态、标签或更小的父问题范围进行缩小。不要截断问题集合或自动将其拆分为多个结果载荷。

## 连接器故障处理

在决定如何处理之前，先对失败的 Jira 或 Linear 读取进行分类：

- **缺少连接器或认证：** 连接器工具不可用、来源未连接，或认证缺失或已过期。不要重试。说明无法访问哪个来源，并请用户连接或重新授权。同时提供在用户粘贴完整发现内容时继续处理的选项。
- **权限不足：** 连接器已认证，但报告禁止访问、拒绝访问或等效的授权错误。不要重试。保留连接器的安全错误详情，请用户请求访问权限或使用具有访问权限的账户，并提供粘贴发现的替代方案。
- **问题未找到或无法访问：** 精确的标识符或 URL 未返回匹配的问题，或连接器无法区分不存在与隐藏。不要声称该问题不存在。请用户验证标识符和来源工作区，或直接提供工单内容。
- **瞬时连接器故障：** 超时、速率限制、临时服务错误或传输故障可能无需配置更改即可恢复。对相同的读取重试一次。重试期间不要扩大查询范围或切换来源。如果相同的重试失败，则停止，并在安全可显示时报告原始错误和重试错误。

在任何未解决的检索失败之后，停止接入工作流。不要检查仓库、规范化发现、分配判定或发出 `triage-finding/v0` 契约。提供与故障类别匹配的恢复步骤，而不是通用的成功形态响应。

## 规范化与溯源

将 Jira 和 Linear 漏洞工单规范化为 `source_type: "scanner_ticket"`，除非工单正文明确表示 `bug_bounty`、`advisory`、`cve` 或 `codex_security_finding` 输入。

在 `input_id`、`normalized_input.references` 以及证据或证明缺口文本中保留问题 key 或标识符、URL、项目、状态、标签、组件、优先级、经办人、报告人、时间戳、问题类型和导入查询。

## 只读默认

默认采用只读导入和分诊。除非用户明确要求写回，否则不要添加评论、转换问题、关闭问题、分配负责人或更改标签。

当请求写回时，首先完成静态判定。总结计划的问题变更，并将变更与证据分析分开。

对于导入的集合，最终摘要必须说明导入的问题数量、查询或问题集合、完整结果的渲染或保存位置，以及源系统是否发生更改。默认状态为：未对 Jira 或 Linear 进行任何更改。
