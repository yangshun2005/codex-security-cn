# 验证指南

在验证候选安全发现时，请使用本指南。

## 实例保持型验证

验证不决定扫描是差异范围还是仓库范围。请使用用户、发现报告或顶层安全扫描工作流提供的范围和候选集。当验证直接针对某个指定缺陷被调用时，仅验证该缺陷，除非用户明确提供多个实例或要求进行兄弟扩展。

当验证是顶层仓库范围安全扫描的一部分时，即使发现笔记、覆盖台账和重复的源/汇聚点/控制模式尚未编号为最终发现，也应将其视为验证输入。台账是覆盖工件：保留标记为`不适用`、`已抑制`、`已延迟`或`可报告`的行，并继续完成该台账所需的有限高影响兄弟检查。这是保持仓库范围扫描的范围，而不是独立扩展独立的验证请求。

对于大型仓库范围扫描，验证应同时保持覆盖范围和证明深度。一旦候选具有完整的源、最近控制、汇聚点和影响元组，当运行时复现需要不可用的内部服务、机密、服务网格、云账户或生产数据时，优先选择静态跟踪加上现有测试和部署/配置证据，而不是冗长的环境搭建。缺少运行时设置是证明缺口说明，不是反证，也不是抑制理由。

如果发现、用户范围或公告/标签种子指定了特定包、类族或根控制族，验证必须关闭该确切行。相邻路由、解析器、反序列化器或认证流程中的同族发现可用作支持证据，但不能作为种子行的反证。如果种子行仍然存在，请将其确切的根控制文件:行保留到攻击路径分析和最终报告输入中。

公告派生的候选文件、函数或代码块本身不是发现，但它们是公告主导的仓库范围扫描的验证义务。针对检出的本地代码验证它们，然后使用本地证据将每个确切的种子行关闭为`可报告`、`已抑制`、`不适用`或`已延迟`。如果种子文件仅在搜索期间打开，仍应为其提供明确的关闭行，而不是仅留在日志中。

当检出的代码仍包含种子构造时，保持该种子行有效，直到验证决定其本地证明元组。仅当本地仓库证据独立支持相同的源、损坏的控制、汇聚点或安全影响以及现实前提条件时，才将其标记为`可报告`；否则，使用确切缺失的证明或反证将其标记为`已延迟`或`已抑制`。更严格的部署假设、缺失的下游应用程序配置或相邻更强的发现是需要说明的前提条件或证明缺口，本身不是反证。

当高影响候选仅因缺失下游消费者、工作流调用者、策略异常或工件来源事实而被阻止时，在抑制之前，对最可能的证据来源运行一次有限的邻接遍历：生成的客户端/规范、工作流调用者、部署/策略配置、存储或 ACL 定义以及包导入者。如果该遍历仍留下证明缺口，保持该行为`已延迟`，而不是将缺口视为反证。

当输入包含多个候选实例时，保留该实例清单：

- 独立验证每个候选实例，以决定该确切文件/行是否应保留
- 不要仅仅因为多个候选实例共享漏洞家族而将它们合并为一个已验证的发现
- 对于发现或安全扫描工作流提供的重复实例，在可行时验证一次代表性利用路径，然后通过检查相同的证明元组（攻击者控制的源、缺失或不完整的最近控制、危险的汇聚点和影响）来分析验证每个兄弟实例
- 对于重复的易受攻击模板、查询构建器、解析器操作、认证/对象端点或共享辅助调用者，当证明元组适用时，将每个独立易受攻击的文件和汇聚点/控制行保留为存活的实例。仅在每个受影响的实例都有自己的存活发现条目或明确的抑制/延迟行之后，才可接受为可读性进行分组。
- 如果发现向验证提供了具有多个具体汇聚点、解析器、辅助、API 模式或受保护操作行的广泛家族候选，在决定存活之前将其扩展为子关闭行。一个代表性 PoC 可以支持该家族，但每个子项仍需要自己的文件/行、源或受保护边界、最近控制、汇聚点或操作、处置和反证。
- 当一个路由或辅助暴露多个同族操作，如`execute`/`executemany`/`executescript`、`pickle.load`/`pickle.loads`/`yaml.load`/`yaml.load_all`、分离的路径/文件辅助、插入/选择/删除/更新查询构建器或未经认证的创建/删除/重置/管理员/作业操作时，验证或抑制每个独立可触发的操作，而不是仅携带一个代表性行。
- 在验证期间将共享或生成的包装器视为可达性证据。不要让已证明的包装器路径替换决定每个具体实例是否存活的子汇聚点/控制/受保护操作行。
- 在重复的高影响模式具有一个强证明元组后，停止深化该证明，除非额外的运行时工作会实质性改变可报告性、严重性或置信度。将下一个验证工作用于兄弟台账行，并仅使用每个实例的确切反证进行抑制。
- 当兄弟安全时，使用使其安全的特定控制抑制该确切实例。
- 保留`候选 ID`、`文件:行`、`家族`、`验证方法`、`最近控制`、`是否存活`和`置信度`的表。
- 优先选择确切的源/汇聚点行证据，而不是宽泛的散文，因为下游验证、攻击路径分析和最终报告组装依赖于精确的受影响位置。
- 对于包装器到共享汇聚点的发现，验证通过包装器的可达性，同时在该行实现损坏的安全行为时，将底层解析器、反序列化器、路径/归档、表达式或认证/授权汇聚点/控制行保留为受影响位置。
- 对于解析器、反序列化器和对象构造发现，验证执行递归解析、类型解析、转换、类过滤或对象构造的具体编解码器、转换器、反序列化器、解析器或容器处理程序。宽泛的解析器/配置证明不能关闭具体的注册处理程序，除非该处理程序自己的根控制行被包括或确切抑制。
- 对于文件格式对象模型辅助行，首先决定格式错误或对抗性输入是否可能到达辅助，以及缺失的类型、大小、形状、递归、数字或转换保护是否造成崩溃、拒绝服务、解析器混淆、授权绕过或其他具体安全影响。如果这些部分缺失，使用确切证据抑制或延迟该行；如果存在，即使边缘解析器/过滤器发现也存活，也将辅助行保留为根控制。
- 当等效的类过滤器、允许列表、拒绝列表、黑名单、白名单或解析器控制跨运行时包重复时，分别验证或抑制运行时/导出实现。传输调用点或嵌套辅助证明可达性，但可复用的解析器行在实现损坏的安全行为时仍受影响。
- 如果验证显示一个路由或辅助具有多个不同的高影响证明元组，保持它们可单独寻址，而不是用一个替换另一个。已证明的命令注入路径不能验证掉同一流程中单独的 SSRF、XML 解析器、路径/文件、XSS/模板或授权/状态更改路径。
- 当抑制 XML/解析器/反序列化器候选时，指明击败该解析器路径的确切完整控制。部分加固或安全的兄弟解析器不能抑制不同的默认工厂、转换器、验证器、转换器、解组或解析调用。
- 对于 XML 解析器/转换器候选，验证加固在确切解析器实例上失败关闭。`FEATURE_SECURE_PROCESSING` 本身、吞没/记录的`setFeature`失败、调用者提供的解析器工厂/读取器或缺失的实体/DTD 解析器控制使行保持有效，除非确切的运行时证据证明外部实体和 DTD 无法被处理。
- 对于命令/操作运行器候选，独立验证每个参数类型和执行模式。即使前端小部件通常会约束它们，也将 API/Webhook 提供的值视为攻击者控制的，并且不要抑制 shell 注入，直到该参数类型的确切类型检查/转义路径在模板渲染和 shell 包装之前被证明安全。
- 对于 SSRF/下载/Webhook/回调候选，验证确切的目标来源、URL 解析器、允许/拒绝/过滤配置、重定向行为和网络客户端汇聚点。不要因为出站请求是文档化功能、操作员可以配置过滤器、过滤器默认空或验证发生在重定向之前而抑制；这些事实是前提条件或部分控制，除非最终请求的目标在确切路径上受到约束。
- 对于资源服务/路径遍历候选，验证该处理程序使用的确切允许列表、路径匹配器、URL 解码、规范化和资源选择控制。较新的安全资源处理程序或解析器不能抑制具有不同控制行的旧版/已弃用/导出处理程序。对于恢复/导入/导出/管理员外观路由，在假设路径已认证之前，还要验证确切的全局中间件和装饰器语义；当路由在默认或无密码部署中无需认证即可到达时，可选或有条件的登录包装器是不够的。
- 对于恢复/导入/导出、备份/恢复、归档提取、文件复制/移动、下载/打开和密钥/配置获取候选，验证该操作的确切目标选择、规范化、分支本地转换和文件系统效果。附近的认证绕过、机密泄漏或配置缺陷是单独的行，不是路径/文件行的抑制或替换。
- 对于归档提取和恢复/导入候选，抑制需要确切证明每个不受信任的成员路径在提取或写入发生之前被规范化并包含在内。不要使用库辅助安全的通用声明，或使用后来的顶层文件过滤、UUID/清单门、copytree/导入允许列表、递归提升到批准的根目录或攻击者控制的路径已实现后的提取后扫描来抑制。每当提取的内容后来被复制或提升时，明确推理符号链接、硬链接、元数据和导入子树行为。不要要求写入逃逸整体应用/数据存储根目录；写入该根目录内受信任的配置、对等对象目录、共享根目录或导入子树仍算作任意文件影响。
- 对于归档成员遍历，当上传的包/归档字节到达成员名称解码/过滤/连接/写入序列且写入前没有确切包含检查时，静态证据可能足以存活。缺失可选解析器库或缺乏完整归档工具应降低置信度或成为明确的延迟证明缺口，而不是静默抑制或用相邻的同族文件遍历替换该行。
- 弃用、选择加入注册或文档警告 API 可能危险是框架/库运行时代码的前提条件，而不是反证，当实例具有合理的跨边界源和运行时/部署路径时。仅当仓库证据证明预期的受限/控制模式击败确切攻击时才抑制；不要因为无限制模式被记录为危险而抑制受限模式的绕过。
- 当抑制认证/授权候选时，指明该端点上的确切权限、认证、租户/对象或状态转换检查。其他地方的凭据辅助问题不能替换读取受保护数据或触发受保护工作的公共 Webhook/状态/API 端点。
- 对于有状态认证协议，验证从预认证或预升级状态到凭据身份的转换：主体/凭据/令牌安装、重新绑定或重新认证调用、颁发者/回调分配以及验证对象与消费对象。当攻击者控制的协议状态可以认证或绑定错误身份时，缺失重新绑定或不完整状态检查仍可报告。
- 对于自助更新候选，逐字段比较攻击者控制的请求对象和持久化对象的安全敏感身份、信任状态、租户、角色/组、MFA 和账户恢复属性。不要因为检查了一个别名（如主电子邮件）而抑制，当相关的标量或集合别名仍可更改时。
- 当提供的候选集是仓库范围时，首先验证高影响候选，并按此顺序投入验证工作：命令/代码执行、不安全反序列化、SSTI/模板执行、SQL/NoSQL/查询注入、SSRF/回调/文件/网络影响、路径遍历/任意文件读取或写入、不安全上传以及具有权限或受保护对象影响的授权/租户/对象绕过。
- 不要让低严重性数据/配置发现在高影响队列耗尽之前消耗验证预算。
- 不要让一个困难的构建或服务设置消耗验证覆盖台账中兄弟高影响候选所需的预算。如果设置变得不成比例，切换到代码跟踪加上该候选的现有测试/配置证据，并继续台账。
- 抑制必须关闭它们抑制的特定行。缺失下游调用者、部署事实、导入路径或工件来源事实是运行有限邻接遍历或将行标记为`已延迟`的理由，而不是候选安全的证明。

使用类特定证明元组：

- 授权/租户/对象/状态更改：攻击者路径 + 缺失/错误保护 + 受保护对象/比较/状态转换
- 注入/路径遍历/文件上传/标头/开放重定向：攻击者控制的字节 + 清理器/规范化/允许列表结果 + 危险汇聚点/上下文
- XSS/模板/SSTI：攻击者控制的值 + 转义/模板上下文 + 浏览器/服务器端模板执行汇聚点
- 递归占位符/模板注入：请求、租户/客户端元数据、存储配置或错误值 + 递归扩展、重新解析或评估解析值的占位符/模板辅助 + 缺失转义/非递归保护 + XSS、表达式执行、凭据泄露或代码执行影响
- 反序列化/代码执行：攻击者控制的序列化/代码/模板字节 + 不安全的加载器/评估器 + 执行或对象构造效果
- 反序列化器包装器拒绝列表/允许列表控制：攻击者控制的、存储的、插件、远程、导入或持久化状态序列化输入 + 接受类型标签或默认对象构造的共享包装器 + 缺失/顺序错误的拒绝条目、允许列表缺口、转换器优先级缺口或不安全的类加载器/默认转换器行为 + 对象构造、崩溃、代码执行或权限边界影响
- 具体反序列化器/编解码器控制：攻击者控制的序列化或结构化输入 + 注册的编解码器/转换器/反序列化器/容器处理程序，递归解析、解析类型、过滤类、转换值或构造对象 + 缺失验证、不安全回退、失败开放过滤器或无界遍历 + 代码执行、对象构造、解析器混淆、拒绝服务或权限边界影响
- SSRF/回调：攻击者控制的目标 + 目标控制绕过 + 网络/读取/副作用影响
- SSRF 可选过滤器/重定向控制：攻击者控制的下载/Webhook/回调 URL + 可选、默认空、仅正则、仅请求前或跟随重定向的目标控制 + 内部/LAN/云元数据/文件支持的获取或服务器端回调副作用
- 认证/令牌/断言/协议控制：攻击者控制的令牌、断言、协议元数据或版本值 + 确切验证器/控制语义 + 验证值与受信任值不匹配、不完整规范化/相等性、未检查解析或缺失绑定 + 认证、授权或协议安全影响
- 有状态认证协议转换：攻击者控制的凭据、主体、令牌、颁发者、断言、服务器响应或协议元数据 + TLS 升级、绑定、重定向、回调、断言验证或身份提供者响应后的状态转换 + 缺失重新绑定/重新认证、陈旧身份重用、不完整颁发者/回调绑定或验证与消费不匹配 + 认证绕过或身份混淆影响
- SAML/XML 断言绑定：攻击者控制的响应或断言集 + 一个对象的协议/签名验证 + 后来使用、克隆、序列化或存储不同的断言/文档节点 + 认证/会话/令牌影响。应陈述多对象前提条件，但抑制需要确切证据证明同一对象在密码学和语义上绑定到消费对象。
- SSO/SAML 响应验证器：攻击者控制的包含一个或多个断言的 SSO 响应 + 选择、索引、克隆、序列化或返回断言的响应/断言验证器代码 + 签名/验证断言与后来会话/令牌路径消费的断言不匹配，或缺失接收者/受众/目的地/ACS 绑定 + 认证或授权绕过影响。通用声明授权器或服务方法授权发现不能验证或抑制此行。
- 发现有效选择不匹配：攻击者控制的令牌/断言/身份列表或集合 + 验证器循环或`foundValid*`标志证明一个元素，而后来固定索引、第一个/最后一个、克隆、序列化或查找消费另一个元素 + 认证、授权或协议状态影响。抑制需要证据证明消费对象是已验证的同一对象。
- XML 解析器/转换器加固：攻击者控制的 XML/SVG/XSLT/SAX/DOM/StAX 输入 + 解析器工厂、转换器、转换器或解析器设置 + 失败开放功能配置、缺失实体/DTD 控制、调用者提供的解析器路径或仅安全处理加固 + XXE、SSRF、文件读取、解析器注入或拒绝服务影响
- 查询/解析器注入：攻击者控制的字节 + 接收语法或运算符而不是绑定值的查询/选择器/解析器 API + 语义更改、解析器错误、行集更改、写入放大或可绕过的查询后保护 + 读取、写入、授权、完整性或可用性影响。后续业务检查仅在证明其检查同一受信任对象并击败该确切实例的语法控制后限制置信度或影响。
- 资源处理程序路径控制：攻击者控制的 URL/路径/资源名称 + 允许列表/路径匹配器/解码器/规范化器/资源选择控制 + 不匹配、预解码/后解码缺口、旧版处理程序行为或不安全解析器回退 + 任意文件读取/写入、路径遍历或未经授权的资源访问影响
- 共享反序列化控制：攻击者控制的或具有权限的序列化/配置/导入/插件/远程输入 + 共享加载器或转换器/允许列表/拒绝列表行为 + 不安全对象构造或不完整控制 + 受影响调用点或未解决的跨边界重用
- 协议/版本解析器：攻击者控制的协议元数据 + 在拆分/解析/比较之前缺失完整格式强制 + 解析异常、错误排序或功能门绕过 + 协议安全影响
- 协议/版本回归种子：CVE/公告/安全测试上下文指向协议兼容性、版本比较、协商或功能门控 + 检出的实用程序/比较器使用`split`、数字转换、正则部分验证或未检查组件访问解析攻击者控制的协议元数据 + 格式错误或对抗性元数据可能崩溃协商、绕过协议门、选择错误功能路径或降级/禁用安全相关行为。当本地解析器/控制/影响元组可见时，缺少运行时工具是置信度限制。
- 文件格式对象模型 DoS/损坏：不受信任的文档/归档/消息解析为第一方对象模型 + 执行未检查元素转换、递归、数字解析或无界迭代而不验证攻击者控制结构的低级数组/字典
