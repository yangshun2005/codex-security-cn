# Codex 桌面标准扫描

仅当主机明确标识自身为 Codex 桌面应用后，才阅读此参考。所列工具本身并不能确立桌面主机身份。

## 解析权威扫描

在开始扫描之前，先解析目标、请求范围以及用户提供的安全上下文。

- 如果请求已包含 `scanId`，则调用 `get_codex_security_scan_context`，并在提供时传递 `handoffClaimToken`，然后继续该现有扫描。
- 否则，使用 `mode: "standard"`、`targetPath`、`scope` 以及任何确切的 `userContext` 调用一次 `start_codex_security_prompt_only_scan`。要求其提供权威的 `scan.scanId` 和 `scan.scanDir`；在提供时保留其交接令牌。
- 如果直接启动失败或返回格式错误的上下文，则直接呈现该错误。不要虚构扫描所有权、启动替代扫描、打开设置或切换到终端工作流。

在整个父工作流中使用返回的 `scanId`、`scanDir`、范围以及确切的 `userContext`。仅在此权威上下文存在后，才阅读 `../../../references/desktop-config-preflight.md` 并运行能力预检。

对实际发生的工作使用现有的桌面阶段标签：威胁建模、调查、父级主导验证、攻击路径评估和报告汇编。保留权威扫描 ID 和交接令牌。在分派每个新发现的作业之前，增加调查员总数；并发运行的基线是独立的，不会增加该总数。在推进其 `review_receipts` 进度计数之前，将每项已完成且基于来源的调查记录为真实的覆盖范围。不要创建单独的收据文件。仅在相应的发现或报告产物存在后，才推进后续阶段计数，并且绝不虚构计数、阶段工作人员或覆盖范围。

## 完成同一扫描

使用 `record_codex_security_scan_draft({ scanId, handoffClaimToken?, scope?, threatModel?, findings, coverage })` 记录一次完整的语义扫描草稿。提供实际的发现、基于来源的覆盖范围以及保留的威胁模型；让工作台写入未封装的规范产物，并派生权威目标、范围、覆盖范围元数据、发现标识和指纹。

在完成之前，满足桌面端对任何逐项发现报告交接的要求。在语义草稿成功且所有三个规范 JSON 文件存在后，使用相同的权威扫描 ID 和交接令牌恰好调用一次 `complete_codex_security_scan`。仅在完成成功且 `report.md` 存在后才返回，并链接生成的报告和规范产物；仅当用户明确请求时才检索完整发现。在可用时包含测量的令牌使用量，并明确标注部分或不可用的测量结果。

对于每个报告的发现，在其最紧密的 `root_control` 位置（或当无法识别根控制时，在最相关的受影响源代码位置）发出一个 `::code-comment{title="[<优先级标签>] <标题>" body="<说明>" file="<绝对路径>" start=<行号> end=<行号> priority=<优先级编号> confidence=<0到1>}` 审查指令。将 `critical`、`high`、`medium` 和 `low` 分别映射到 `P0/0`、`P1/1`、`P2/2` 和 `P3/3`；保持其标题和说明与生成的报告一致。

如果最终化失败，则呈现确切错误并保留持久化扫描以供后续继续；不要在同一响应中重试完成、生成替代报告或声称成功。
