# 扫描产物与工作台账

本参考仅适用于需要可审计候选覆盖范围或变更文件审查工作清单的差异扫描。标准扫描和深度扫描不使用本参考。

## 产物要求

- 从 `../../../references/scan-artifacts.md` 加载每次扫描的威胁模型路径，作为仓库特定的威胁模型事实来源。
- 使用 `../../../references/scan-artifacts.md` 中的产物路径：`seed_research.md`；当需要限定范围的文件审查工作清单时使用 `deep_review_input.jsonl`；当需要限定范围的文件审查工作清单时使用 `work_ledger.jsonl`；当需要聚合多个文件审查结果时使用 `raw_candidates.jsonl`；当需要跨文件去重时使用 `dedupe_report.md` 和 `deduped_candidates.jsonl`；以及每个发现的 `05_findings/<candidate_id>/candidate_ledger.jsonl`。

## 种子研究

- 首先捕获用户提供的范围提示，如 CVE/GHSA/安全公告标识符、软件包版本、命名的漏洞家族或发布/安全测试参考。
- 当用户请求或扫描上下文包含 CVE、GHSA、公告、Issue、发布版本、软件包版本或明确的漏洞家族标识符时，在深度前沿扫描之前运行一次公告种子遍历，并将其保存到 `../../../references/scan-artifacts.md` 中的公告种子研究路径。
- 在授权的源状态下使用相关的安全指南、用户提供的公告文本和已检出的安全测试。仅在用户明确授权时访问外部来源；不要检查无关的 Git 历史或后续修复。记录搜索的来源、候选文件/函数/类/代码块、预期的易受攻击行为以及任何失败的查找尝试。
- 仅将这些候选视为种子行：在报告之前，针对已检出的仓库验证易受攻击的行为。不要让种子通道取代扫描的主要范围。
- 当公告上下文具有通用或无帮助的类别时，首先检查提供的公告文本和范围内的安全测试。如果该证据不确定，则针对项目特定的协议、解析器、验证器和实用程序名称以及公告术语运行本地回归种子遍历；不要假设明显的热点是预期的安全回归。
- 当种子遍历或本地搜索打开候选文件、类、包或代码块时，在该区域进行机会性同族扫描之前，先创建一条精确的种子目标行。对该文件/包及其直接共享的辅助函数或调用者链运行简短的种子优先分类，然后将该行关闭为 `reportable`、`suppressed`、`not_applicable` 或 `deferred`。也可以报告更明显的邻近问题，但不能取代种子目标行。
- 保持每个用户/公告/标签种子的边界包或类族开放，直到该精确区域被关闭为 `reportable`、`suppressed`、`not_applicable` 或 `deferred`。邻近解析器、认证流程、反序列化器或模板引擎中更广泛的同族发现不会隐式关闭种子行。
- 在公告主导的扫描中，将公告、修复代码块、发布说明或安全测试视为预期根本原因的证据，而不是排他性过滤器，也不是裸发现。保持精确的种子行开放，直到已检出的仓库证据独立支持或反驳相同的来源、被破坏的控制和影响元组。

## 子代理要求

- 当扫描使用子代理调度阶段且当前工具集中有可用的子代理时，使用子代理执行这些阶段。
- 显式调用顶级差异扫描即授权该工作流所描述的子代理调度阶段。
- 对于 JSONL 工作清单阶段，生成的工作进程数不超过运行时的可用槽位数，等待其具体的 worker id，验证每个结果，然后重新填充可用槽位。如果生成被拒绝，由父代理完成未开始的工作，不缩小覆盖范围。在原生 v2 上，使用 `fork_turns=none` 生成自包含的工作进程；仅在重试前使用 `interrupt_agent` 停止仍在运行的工作进程。
- 在每次委派的文件审查、验证或攻击路径调度之后，立即发出 `CODEX_SECURITY_WORKER_STATUS {"phase":"file_review","planned":6,"started":3}`，包含实际的阶段和 worker 数量，包括没有 worker 启动的情况。不要包含 worker id、路径、提示、错误或其他字段。
- 文件审查子代理所有权：一个文件审查子代理拥有一个 `deep_review_input.jsonl` 行或一个非常小的紧密耦合分片，最多 5 个文件，并返回该任务的完整文件回执和去重前的发现对象。
- 文件审查子代理相对于被审查的目标代码是只读的，但允许并期望其在已解析的编号产物目录下写入扫描产物，包括 `<discovery_dir>/work_ledger.jsonl`、`<discovery_dir>/raw_candidates.jsonl` 中的原始候选片段，以及当这些产物路径在提示中提供时 `<findings_dir>/<candidate_id>/` 下的每个候选台账回执。
- 验证子代理所有权：一个验证子代理拥有一个候选发现、一个去重后的候选，或一个需要验证关闭的仓库覆盖台账行。它写入或返回验证产物、可见的验证报告更新以及该任务的验证候选台账回执。
- 攻击路径子代理所有权：一个攻击路径子代理拥有一个已验证的候选发现或一个可报告/延期的验证关闭行。它写入或返回攻击路径事实、严重性/策略分析、可见的攻击路径报告更新以及该任务的攻击路径候选台账回执。
- 父代理所有权：父代理拥有 `deep_review_input.jsonl` 生成、有界子代理调度、工作台账和候选台账对账、子代理输出的聚合、需要时的跨文件去重以及最终扫描关闭。
- 子代理提示必须携带其应遵循的精确当前扫描指令。不要依赖子代理隐式继承此技能、其他阶段技能、先前的父上下文或摘要化的参考名称。

### 文件审查子代理交接

父代理应给予每个文件审查子代理足够的具象上下文，使其能够执行分配的行，而不依赖隐式的父上下文。保持提示简洁，但包括：

- 分配的 `deep_review_input.jsonl` 行或微小分片
- 扫描目标、扫描模式、`repo_name`、`scan_id`、`artifacts_dir`、相关的编号产物目录以及每次扫描的威胁模型路径或摘要
- `<discovery_dir>/work_ledger.jsonl`、`<discovery_dir>/raw_candidates.jsonl` 以及 `<findings_dir>/<candidate_id>/` 下每个候选台账回执的可写产物路径
- 任何用户提供的应影响覆盖范围的比较或种子产物，如 HTML/Markdown 报告、先前的安全审查输出、公告文本、CVE/GHSA、发布说明、Issue 或单独的审计目录
- 期望完整读取分配的文件，仅读取生成具体发现所需的支持文件，并返回或写入完整文件回执、原始候选、抑制/延期行和台账回执

父代理必须拒绝或重新提示任何缺少完整文件回执、遗漏候选的来源/控制/汇聚点/影响、遗漏已报告候选的候选本地验证或攻击路径事实，或仅返回“未发现错误”而未以证据关闭分配行的文件审查子代理结果。

### 验证与攻击路径子代理交接

在发现和去重之后，当多个候选或覆盖台账行需要关闭且解析的扫描授权下子代理可用时，将验证和攻击路径工作分配给子代理。

对于验证子代理，包括候选或台账行、发现证据、相关的原始/去重候选 id、受影响文件、威胁模型上下文、验证产物/报告路径以及需要验证回执的候选台账路径。验证子代理应仅保留或抑制分配的实例；它不拥有最终报告组装或无关候选。

对于攻击路径子代理，包括已验证的候选或验证关闭行、验证报告路径或摘要、受影响的根控制和汇聚点行、威胁模型上下文、攻击路径报告路径以及需要攻击路径回执的候选台账路径。攻击路径子代理应仅为分配的实例生成可达性、反证、严重性/策略分析和最终可报告性事实。

父代理必须在最终报告之前对验证和攻击路径子代理输出进行对账。当任何可报告、抑制、不适用或延期的候选/台账行缺少所需回执或明确的证据缺口原因时，不得最终确定。

## 限定范围的深度审查

- 使用 `deep_review_input.jsonl` 作为差异扫描的规范变更文件审查工作清单。
- 对于差异限定范围的扫描，从变更的类源文件确定性生成 `rank_input.jsonl`，使用 `<python_command> <plugin_dir>/scripts/generate_rank_input.py make-diff-rank-input --repo <repo_root> --base <base> --mode revisions --head <head> --out <discovery_dir>/rank_input.jsonl` 用于 PR、提交和分支差异，或 `<python_command> <plugin_dir>/scripts/generate_rank_input.py make-diff-rank-input --repo <repo_root> --base <base> --mode local-patch --out <discovery_dir>/rank_input.jsonl` 用于本地补丁，然后使用 `<python_command> <plugin_dir>/scripts/generate_rank_input.py copy-deep-review-input --rank-input <discovery_dir>/rank_input.jsonl --out <discovery_dir>/deep_review_input.jsonl` 将每一行复制到 `deep_review_input.jsonl` 中。
- 差异限定范围的扫描在深度审查之前不对变更文件进行排名或丢弃。差异 `rank_input.jsonl` 中的每一行必须复制到 `deep_review_input.jsonl` 中并获得完整文件审查回执。
- 仅当仓库证据表明需要直接支持文件来理解变更的安全行为时，才添加这些文件；在工作台账或逐文件结果中记录添加回的原因。
- 对选择到 `deep_review_input.jsonl` 中的每个文件进行深度审查。
  - 使用 `<discovery_dir>/work_ledger.jsonl` 作为声明和完成的仅追加记录，并针对 `deep_review_input.jsonl` 进行对账，以确保行不被跳过或重复计数。
  - 在解析的扫描授权下，当子代理可用时使用子代理。
    - 文件审查子代理必须完整读取每个分配的文件，更新这些文件的台账回执，并返回该任务的原始发现结果。
    - 当文件审查子代理在其分配的文件或分片中发现合理发现时，该子代理应在交回之前将该发现推进到候选本地验证和候选本地攻击路径分析。原始结果应包括来源或特权边界、最接近的相关控制、汇聚点或被破坏的控制、影响、验证方法/证据或精确证据缺口、攻击路径事实和处置。
    - 文件审查子代理可以读取验证或解释其发现的发现所需的最少支持文件，但不拥有无关行或最终扫描关闭。
  - 如果子代理不可用，则以相同的完整文件标准自行遍历 `deep_review_input.jsonl`。
  - 文件因出现在搜索中而不算已覆盖。仅当负责的子代理或父代理返回显示文件已被完整读取的回执时，才算已覆盖。
  - 在 `<discovery_dir>/work_ledger.jsonl` 中记录文件级完成、处置和简洁的证据说明；不要创建单独的逐文件发现目录。
  - 当多个文件审查结果被聚合或需要跨文件去重时，将规范化、去重前的候选对象追加到 `<discovery_dir>/raw_candidates.jsonl`。
  - 在 `deep_review_input.jsonl` 中的每一行都有完成回执之前，不要停止。

## 候选发现覆盖

- 将候选发现覆盖与文件覆盖分开跟踪。
  - 使用 `<findings_dir>/<candidate_id>/candidate_ledger.jsonl` 作为每个候选发现的仅追加记录。
  - 每个候选发现在最终报告之前必须具有稳定的候选 id 以及发现、验证和攻击路径分析的候选台账回执。
  - 当发现是在限定范围的文件审查遍历期间发出时，应在该发现有资格进行跨文件去重之前记录候选本地验证和候选本地攻击路径分析。
  - 验证覆盖必须记录该候选发现的验证方法、证据或精确证据缺口以及处置。
  - 攻击路径覆盖必须记录该候选发现的来源或特权边界、最接近的相关控制、汇聚点或被破坏的控制、影响路径以及严重性相关事实。
  - 候选发现因出现在报告或 `raw_candidates.jsonl` 中而不算已覆盖。仅当其候选台账显示所需的回执，或缺少证据的明确延期原因时，才算已覆盖。
- 当多个原始候选流需要跨文件去重时，仅在相关候选台账证明所需覆盖之后进行去重。写入 `<reconciliation_dir>/dedupe_report.md` 和 `<reconciliation_dir>/deduped_candidates.jsonl`，保留独立可达的兄弟实例。
- 去重必须保留候选台账可追溯性：每个去重后的候选必须列出其吸收的原始候选 id 和每个发现的候选台账，并且独立可达的兄弟实例必须保持分离。
