# Codex 安全 CLI

Codex 安全是一个围绕 Codex 及其安全插件的轻量级 CLI 和 SDK 封装。请沿用其现有行为，而非构建另一个运行时。

## 威胁模型

CLI 以当前用户身份运行。该账户下的本地工具和子进程并非独立的安全主体。被扫描的仓库可能包含不受信任的数据。其内容、模型输出以及导入的构建产物均不授权访问其他目标、泄露凭据或在已批准路径之外进行写入。

## 保持简洁

- 对于类型、Schema、参数和状态，优先采用单一事实来源。
- 保持 `--to` 作为唯一的通用集成选择器。将其他集成特定选项（如 `--linear-*` 和 `--jira-*`）置于命名空间下；不要泛化在不同集成间语义不同的字段。
- 复用 Codex API 和共享辅助工具，而非添加额外的信任门控或编排。
- 沙箱只需根读取和工作区写入即可。
- 将仓库路径、符号链接、归档文件及其他仓库控制的数据视为不受信任。
- 保留对凭据、不安全路径、扫描完整性以及用户明确请求的设置的防护。
- 不要对本地输入或 Codex 输出添加任意的大小、数量、深度或缓冲限制。仅保留实际安全边界或上游契约所要求的限制。
- 不要让可选的日志记录、进度或成本跟踪中断扫描。仍须强制执行用户请求的限制，例如 `--max-cost`。
- 保留已完成的扫描产物，并保持数据库迁移仅追加。
- 同时支持 Windows 和 Unix。使用平台感知的路径和进程 API，并在相关时测试真实的 Windows 路径和目录链接。
- 对于不合理的情况，倾向于直接流程和清晰报错，而非防御性回退。

## 单元测试

在 `tests-ts/<module>.test.ts` 中添加聚焦的 Bun 测试。覆盖可观察行为、接受和拒绝的输入，以及每个真实的 Bug 或安全边界。

- 使用确定性夹具、注入依赖和合成凭据。避免网络、真实凭据、共享状态、时序敏感断言以及精确 Markdown 措辞的测试。
- 在每个测试后恢复间谍、模块模拟、定时器、环境变量及其他全局更改。在子进程中隔离持久的 ESM 模块模拟。
- 使用独立的临时仓库和输出目录。比较规范化路径并在之后移除夹具；不要更改进程工作目录。
- 使用原生路径辅助工具和参数数组。在相关时覆盖 Windows 驱动器、空格、目录链接、`HOME` 和 `USERPROFILE`、`PATHEXT` 以及文件 URL。
- 在 Linux、macOS 和 Windows 上保持共享测试启用。当打包行为重要时，测试构建或安装的入口点。

在 SDK 目录中，迭代时运行聚焦测试，然后运行包检查：

```bash
bun test --timeout 30000 tests-ts/<module>.test.ts
pnpm run test --seed 12345
pnpm run types
pnpm run format
pnpm run test
```

测试默认按随机顺序运行。要复现失败，请使用 Bun 测试摘要中打印的种子。

实现验证完成后，仅当测试能提供有意义且持久的回归覆盖时，才将其保留在最终变更中。如果它仅仅是可丢弃的实现脚手架、重复现有覆盖，或会增加脆弱或低价值的维护负担，请在提交或发起 PR 前将其移除，且不要将其包含在提交的变更中。
